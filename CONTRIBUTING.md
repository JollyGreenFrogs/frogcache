# Contributing

Read [docs/coding-standards.md](docs/coding-standards.md) before editing — it is
the canonical house standard (synced from `JollyGreenFrogs/.github`). Key points
for this repo: Conventional Commits; PRs required for `main` (no direct pushes);
Woodpecker CI only (`.woodpecker.yml`); functions over classes; models only in
`src/frogcache/data_models/`; files under ~200 lines; docstrings with
Args/Returns/Raises; runtime config is env-only; secrets never committed.

Architecture decisions live in `docs/decisions/ADR-*.md` (ADR-001 owns this
service's design). Never deploy from a feature branch; deploys need explicit
per-occurrence operator approval. And the first rule: **never SSH into servers —
use `docker --context`** (see `deploy/deploy.sh`).

## What counts as a contribution

A contribution is anything merged into this repo or that materially improves
the project. That includes:

- **Code & tests** — fixes, features, refactors in `src/` and `tests/`
- **Docs & decisions** — README, `docs/`, ADRs in `docs/decisions/`
- **Ops & config** — `deploy/`, `Dockerfile`, `.woodpecker.yml`, `seed/artifacts.json`
- **Issues & reviews** — bug reports with reproductions, design feedback, PR reviews

## Human + AI co-authorship (mandatory disclosure)

frogcache is **co-authored by humans and AI assistants**. AI-assisted work is
welcome and must be disclosed, never hidden:

- Every commit ends with the trailers:

  ```
  Generated by Mistral Vibe.
  Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
  ```

- In the PR description, state which parts were AI-generated or AI-assisted
  and confirm a human reviewed the result.
- By opening a PR you certify that you have the rights to submit the
  contribution and that it complies with the license above.

## How to contribute

1. Open an issue first for anything non-trivial (bug, feature, design change).
   Design changes need an ADR in `docs/decisions/` **before** code.
2. Branch from `main` (`feature/…`, `fix/…`, `chore/…`, …) with Conventional
   Commits.
3. Run the CI gate locally before pushing:
   `python -m compileall -q src tests` and `PYTHONPATH=src python -m pytest -q`
   (or `uv run --with pytest pytest -q`).
4. Open a PR to `main` — no direct pushes, 1 approving review required,
   Woodpecker CI must pass. Never deploy from a feature branch.
